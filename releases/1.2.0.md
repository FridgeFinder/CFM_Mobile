## Important Changes

### 1) Notification model refactor
- Subscription preferences model is being replaced with per-fridge notification preferences:
  - Removed: features/auth/domain/models/subscription_preferences.dart (+ generated files)
  - Added: features/auth/domain/models/fridge_notification_preferences.dart (+ generated files)
- New API-backed follow state provider added:
  - Added: core/providers/followed_fridges_provider.dart (+ generated file)
  - Includes cache + server refresh logic and first-follow verification behavior

### 2) Follow/unfollow and profile notification behavior updates
- Notifications repository, profile screen, auth provider, and related map/list/profile widgets were updated to use fridge-level follow preferences and API responses.
- Additional helper introduced for fridge identifier normalization:
  - Added: core/utils/fridge_id_utils.dart

### 3) Backend surface cleanup
- Firebase Cloud Functions package under fridgefinder_flutter/functions was removed.
- Associated docs/config were updated (README, ARCHITECTURE, firebase.json, APP_STORE_PERMISSIONS, privacy/delete-account pages).

### 4) Test suite reshaping
- Many unit/widget tests were updated for provider/model changes.
- New tests added for followed fridges/notification repositories/profile actions.
- Integration-test suite was streamlined with removal of obsolete scenarios.

### 5) Tooling/runtime updates
- pubspec and analysis options changed.
- iOS Package.resolved updated in both workspace/project paths.

### 6) Notification preferences editor
- The per-fridge notification preferences editor now opens as a full-screen dialog, giving notification controls adequate space on compact devices.

### 7) Map marker consistency and interaction
- Map pins reserve the health-bar area whether or not a fridge has a report, so mixed marker states stay aligned and use a consistent icon size.
- No-report and not-at-location fridges use a consistent pale-grey pin treatment.
- Map rotation is disabled to prevent accidental orientation changes while browsing; marker entrance timers are also cleaned up when markers leave the map.

### 8) Firebase environment and distribution safeguards
- App startup now selects its environment from injected `APP_ENV`; production is the default unless development is explicitly requested.
- Development `.env` selection is only honored in debug builds, preventing persisted local state or bundled settings from silently directing a release build to development services.
- iOS configuration now derives the selected GoogleService-Info plist from Flutter `DART_DEFINES`, keeping native Firebase settings aligned with the Dart API environment.
- Both Firebase Hosting callback domains are supported for email-link routing.
- Fastlane verifies the Firebase project embedded in each IPA before TestFlight or App Store upload, preventing environment-mismatched artifacts from shipping.
- A dedicated `Release-dev` configuration and `dev_testflight` lane support development-environment TestFlight builds separately from production releases.
- Production Fastlane guards now resolve from the Flutter app root, and the iOS app framework declares a minimum supported iOS version of 15.0 for App Store validation.

### 9) Email magic-link sign-in
- Firebase email magic-link sign-in flow added:
  - Added: fridgefinder_flutter/lib/src/core/services/magic_link_auth_service.dart
  - Updated: fridgefinder_flutter/lib/app.dart, core/providers/auth_provider.dart, features/auth/data/repositories/auth_repository.dart, features/auth/presentation/widgets/sign_in_widget.dart
- Full-screen sign-in entry points updated from drawer/profile/my-fridges/follow flows.
- App Links / Universal Links release plumbing added:
  - Updated: fridgefinder_flutter/android/app/src/main/AndroidManifest.xml
  - Updated: fridgefinder_flutter/ios/Runner/Runner.entitlements
  - Added hosting metadata under fridgefinder_flutter/firebase_hosting/public/.well-known/
