Date: 2026-08-07

## TL;DR Summary

- Added environment-aware Firebase bootstrapping so the selected Dev/Prod environment is applied consistently across Auth, Functions, and Messaging while keeping app data flowing through the backend APIs.
- Major architecture shift: the app now relies on backend APIs as the source of truth for fridge data rather than local or realtime database-driven data paths.
- Hardened map tile fallback behavior so the map reliably falls back to raster layers when vector tile API keys are missing or invalid.
- Added a safer iOS launch workflow for macOS to reduce simulator and code-signing failures from Desktop/cloud-synced locations.
- Updated iOS project/runtime wiring (including SceneDelegate/Swift package references) to support stable modern iOS launch behavior.
- Expanded release documentation and test coverage for map/auth screens and tile fallback behavior.

## Major Changes

- Backend API migration is now a core release highlight.
  - The app’s fridge data flow is now aligned around backend APIs as the source of truth.
  - This reduces reliance on local or realtime-database-style data handling for core app behavior.
  - It improves consistency for environment-specific app behavior while keeping data access centralized in the backend layer.
- Firebase environment switching is now enforced at app bootstrap.
  - Added replacement logic for a pre-initialized Firebase default app when it does not match the selected environment project/app ID.
  - Added guard/logging paths when the switch cannot be completed in-process and restart is needed.
  - Updated environment assumptions in auth, messaging, and related service documentation/comments to reflect selected-environment behavior while preserving backend-API data access.
- Map tile resilience and fallback logic improved.
  - Added explicit API key validation helpers for Protomaps and MapTiler.
  - Added one-time warning behavior for missing/invalid keys to avoid repetitive logs.
  - Map screen now short-circuits to raster fallback if Protomaps key is missing.
  - Attribution logic now reflects actual active source based on key presence and vector style availability.
- iOS safe-run operational workflow added.
  - New script runs iOS from a safe local folder under ~/Developer and rsyncs project files first.
  - Script excludes common generated/cached directories to reduce signing/build flakiness.
  - README now includes a dedicated reliable iOS launch section and troubleshooting steps.
- iOS project integration updated.
  - Added SceneDelegate based on FlutterSceneDelegate.
  - Added Swift package resolution artifacts and updated Xcode project references/framework wiring.
  - iOS framework plist was adjusted (MinimumOSVersion entry removed from AppFrameworkInfo.plist in this commit).

## Minor Changes
